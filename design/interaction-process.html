인터랙션 설계 과정

XU Wireflow Review | 포트폴리오 메인·상세 리디자인 — 인터랙션을 어떤 고민으로 정했고, 어떤 순서로 진행했는지 정리합니다.

1. 원칙

기능보다 탐색의 편의인터뷰 문제는 대부분 "기능이 없다"보다 "있는 줄 몰랐다"였습니다. 그래서 움직임은 정보를 찾는 데 도움이 될 때만 넣었습니다.
내용은 직접 쓴 것만다른 사람의 사이트 문구, 이미지, 스타일은 옮기지 않고 구조와 움직임의 방식만 참고했습니다.
스크롤 연동은 한 번에 한 가지화면 전환, 등장, 연속 이동이 겹치면 어디를 봐야 할지 흐려집니다.
움직임 줄이기 설정 존중사용자가 움직임 줄이기를 켜면 모든 등장 효과를 끄고 최종 상태만 보입니다.

2. 진행 순서

① 메인 등장과 스크롤 (메인)섹션이 화면에 들어오면 아래에서 위로 나타납니다. 앵커 이동은 부드럽게 합니다. 스크롤 등장
② 프로젝트 상세의 플로팅 탐색 (상세)이전·다음·홈 버튼을 화면 모서리에 고정하고, 끝에 도달하면 다음 프로젝트를 안내합니다. 맨 위로 버튼은 화면을 한 번 이상 내린 뒤에만 나타납니다. 플로팅 네비
③ 03 프로젝트 카드 (프로젝트)처음에는 화살표와 드래그로 넘기는 목록이었습니다. 이후 가운데 카드를 강조하고 양옆을 작게 줄이는 방식으로 바꿨습니다. 마우스 휠로도 한 장씩 넘어갑니다. 최근 프로젝트 앞에 "추후 업데이트 예정" 카드 두 장을 두고, 마지막 카드 옆의 둥근 버튼을 누르면 맨 처음 카드까지 한 장씩 지나갑니다. 캐러셀휠
④ 03 등장 액션 (프로젝트)섹션에 들어설 때마다 카드가 가운데에 모였다가 좌우로 펼쳐집니다. 바깥 카드일수록 조금 늦게 움직입니다. 스크롤 트리거
⑤ 상세 캡처 필름스트립 (상세)화면 캡처를 가로 한 줄로 놓고 드래그와 스와이프로 넘깁니다. 필름스트립
⑥ 히어로 코드 패널 (메인)코드가 한 줄씩 나타나고, 휠을 위로 올리면 다시 숨겨집니다. 아래로 내리면 다시 한 줄씩 나타납니다. 스크롤 상태
⑦ 경력 그래프 (경력)섹션이 화면을 지나가는 동안 그래프 카드가 위치에 따라 조금씩 움직입니다. 패럴랙스
⑧ 기술 툴팁 (기술)라이브러리 칩에 마우스를 올리면 어디에서 썼는지 보입니다. 기본 언어와 도구는 툴팁이 없습니다.

3. 검토한 대안과 버린 이유

  • 참고 페이지의 카드 부채꼴 방식(통째 복제): 스타일시트를 그대로 옮기는 것은 다른 사람의 작업을 복제하는 것이므로 하지 않았습니다. 기능만 참고해 직접 구현했습니다.
  • 가로 스크롤만 사용한 목록: 현재 위치가 드러나지 않아 가운데 강조 방식으로 바꿨습니다.
  • 자동 재생 캐러셀: 읽는 중에 화면이 바뀌어 사용성을 해친다고 판단해 넣지 않았습니다.

4. 확인과 남은 과제

  • 데스크톱과 모바일 폭에서 각 인터랙션의 동작은 자동 테스트로 확인했습니다.
  • 실제 기기에서의 체감 속도와 터치 드래그는 직접 확인이 필요합니다.
  • 아이콘은 Remix 아이콘 모양으로 맞추는 중입니다. 메인 소스로 옮기는 작업이 남아 있습니다.
